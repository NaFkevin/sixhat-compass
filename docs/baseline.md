# HexaMind v0.1 Preview 开发基线

批准日期：2026-10-22；执行报告日期：2026-10-23（Asia/Shanghai）。

目标用户：DSH 独立开发者和个人产品作者。闭环：粘贴计划 → 默认结构化评审（按需六帽深度） → 针对性追问 → 可编辑、可导出的决策卡。

## 阶段边界

A 验证安装、宿主调用、UI、取消、禁用及复现。B 完成第一次产品闭环。C 完善历史与失败处理。D 对照评测和真实用户验证。E 公开 Preview。

首发保持六帽、@ 单角色、固定流程、全局模型继承、群聊、决策卡、历史及失败处理。长期记忆、独立私聊、自动模型回退、动态会议与自定义角色延后。

## 已批准的五处修正

1. 上游版本事实：DS Bot v0.2.0 于 10 月 21 日发布；移除旧消息/轮数计数限制的发布说明属于 v0.1.7。HexaMind 不继承其自主接力控制器。
2. 来源与核验分开：origin = user-material / ai-analysis / external-source；verification = unverified / supported / conflicting / insufficient。外部工具获取资料不等于证实结论。每条 claim 单独关联来源和证据。
3. 只读指模型权限：模型无写文件、执行命令或外部操作工具；插件程序可以保存专属数据和执行用户发起的导出。
4. 六帽深度评审正常 6 个角色生成步骤；每步骤最多 1 次自动重试，每次评审最多追加 2 次。认证失败、未知模型、用户取消不重试。模型修复 JSON 消耗同一预算。追问/手动重试独立归因并计入实际总量。Phase A 为 1 次单帽调用，自动重试为 0。
5. A 增加取消/禁用清理与两个不同角色的指令注入验证；继承语义明确为 agentDefaultModel.currentSelection() 的全局默认值，不是当前打开聊天的选择。每次新调用重新读取，进行中保留快照。

## 不变量

- 控制器安排调用，模型不得递归召唤模型。
- 停止后不再调度，不接纳迟到内容；已生成内容保留。
- 不能保证取消后供应商立即停止计算或停止计费，报告明确这一限制。
- AI 不填用户最终决定。缺证据允许空列表并说明缺口，不允许伪造来源。
- 不强制依赖 DS Bot、Our Free Model 或新 API 网关。
- 版本及锁文件进入交付；未实测平台不标为兼容。

## Phase B 固定顺序

白帽整理 → 红/黑/黄/绿独立审视（不读取彼此首轮回答）→ 蓝帽汇总为决策卡。四帽仍可串行执行来避免超出供应商并发限制，认知独立不等于必须并发。

Phase B 首个验收材料为本项目计划，必须完成一次针对性追问及 Markdown 导出。Phase A 的示例是公开、简化的测试文本，不冒充完整闭环。

## Phase E 获批调整

用户依据Phase D同意：默认结构化单次评审，六帽按需。默认正常1次、最多1次自动重试；六帽预算保持原规则。追问和人工恢复另计。真人验证仅准备材料，未采集实际结果；发布说明必须明确。旧mode=review历史不改成单次。

## 2026-10-24 原生交互修订（用户明确批准）

日常入口为 DSH 原生 @单帽自然语言回复；独立设置页控制可用状态与展示，操作区移除配置表单。结构化与六帽变为主动高级入口，旧记录与API语义保留。新增 hat-chat 和信封4，升级前原样备份。锁定宿主的纯命令空白会话复用，明确使用不调用模型的 @新讨论 和记录页返回原对话作为替代，不伪造普通轮次。


## 2026-10-24 试用反馈修订

用户要求修复发送后草稿延迟清空，改名六帽规划并准备GitHub发布。nativeStart在持久化受理后返回，生成继续；旧native API保持完整结算。包名改为dsh-liumao-planner，内部hexamind标识维持兼容。仅做本地发布准备，不执行远程公开发布。

# 高级评审流程

仅在当前请求明确选择综合评审、六帽评审或生成决策卡时使用。单帽模式不需要此参考文件。

## 综合评审

1. 从可见材料确定本次目标和约束；缺少目标但仍可分析时明确采用的理解，关键材料缺失则先询问。
2. 综合审视信息缺口、可能的直觉反应、风险、收益成立条件、实质不同的替代方案和可执行验证。
3. 给出简洁的综合结论及最值得先验证的事项，不宣称做过独立专家讨论。
4. 使用 [决策卡模板](../assets/decision-card.md) 输出一张精简卡片，避免在正文和卡片中逐句重复。

## 六帽评审

正文第一句明确说明：“以下是同一模型的六种视角分析，并非六位独立专家；本次未做外部核验。”若当前确有可追溯的核验记录，只调整最后一个分句，如实说明其范围。不能省略同一模型说明。

按白、红、黑、黄、绿、蓝的顺序组织输出，各段只给与该视角相关的发现，不展示内部推理过程：

- 白帽：已提供信息、假设、缺口；为后续视角交代材料边界。
- 红帽：可能的直觉和情绪，明确是模拟反应。
- 黑帽：可观察的失败条件与验证行动。
- 黄帽：收益何时成立、怎样验证。
- 绿帽：不同的替代方案和小实验。
- 蓝帽：汇总目标、分歧、优先级和决策卡。

这是同一模型在当前任务中的多视角分析，不是六位独立专家、六个并行智能体或六次已计费调用。不要捏造未生成的帽子发言；不启动子智能体或外部模型来凑角色。重复观点归并，实质分歧说明其前提和验证办法；可反驳的错误不包装成“双方各有道理”。

## 仅生成决策卡

从已讨论内容提炼卡片，不重新发起完整分析。保留已有的不确定性、失败条件和用户决定。尚无讨论但本次给了原始材料时，只整理该材料能支持的部分，并明确“尚无先前评审”。完全缺少材料时请用户提供，不生成假内容。

## 卡片填写规则

使用 [决策卡模板](../assets/decision-card.md)，填写有依据的内容；未提供的预算、期限、数值阈值、负责人或实验结果写“待补充”，不替用户确定。

- **用户提供**：来自可见的用户材料，仍可能未经核实。
- **AI 分析**：推导、建议、模拟情绪、风险判断、建议的实验与指标。
- **外部核验**：只记录当前可见的真实核验行为、具体来源及它能支持的范围。只有网址或转述时仍列为待核验；没有记录就写“尚未外部核验”。

指标和通过条件若是本次建议，应标注“建议，待确认”；它们不能冒充用户承诺或已完成实验。已有矛盾证据要说明冲突，不能按有利结论筛选来源。

“用户最终决定”默认“待用户填写”。若用户此前明确作出决定，可以保留其原话并标注“用户已明确”，不把模型推荐填进这一栏。后续修改卡片时保留用户决定，除非用户明确更改。

默认直接输出 Markdown，不自动保存或覆盖文件、不伪造导出成功。是否真正创建文件取决于用户另行提出的请求及宿主可用能力。
